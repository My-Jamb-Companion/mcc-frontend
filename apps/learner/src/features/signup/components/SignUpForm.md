# SignUpForm Component

The `SignUpForm` component provides a user interface for creating a new account using an email address and password. It handles form validation, submission logic, and transitions to an email verification view upon successful form completion.

## Overview

This component is a central part of the learner's signup flow. It uses `@mcc/features` for form management and `@mcc/ui` for animations and icons.

## Features

- **Interactive Validation**: Real-time validation for email format, password length, and password matching.
- **Animated Transitions**: Uses `framer-motion` for smooth layout transitions and entry/exit animations.
- **Stateful Navigation**: Can toggle between the signup form and the `EmailVerify` component.
- **Dark Mode Support**: Styled to work across both light and dark themes.

## Form Configuration

The form is managed using a custom `useForm` hook.

### Inputs and Validation

1.  **Email**
    - **Required**: Yes ("Email is required")
    - **Type**: `email`
2.  **Password**
    - **Required**: Yes ("Password is required")
    - **Minimum Length**: 6 characters ("Password must be at least 6 characters")
    - **Type**: `password`
3.  **Confirm Password**
    - **Required**: Yes
    - **Validation**: Must match the value in the `Password` field ("Passwords do not match")
    - **Type**: `password`

## Internal State

- `emailVerify` (`boolean`): Determines whether to show the registration form or the `EmailVerify` success component. It is set to `true` inside `onSubmit`.

## Code Suggestions & Observations

During a review of the implementation, a few points were noted:

1.  **Unused Interface Property**: The `SignUpFormInputs` interface includes an `error` property of type `FieldErrors` which is not used within the form input data.
2.  **Form Values Access**: The component accesses `formState.values.email`. In standard `react-hook-form` implementations, values are typically accessed via `getValues()` or `watch()`. Ensure the custom `useForm` from `@mcc/features` explicitly exposes `values` on `formState`.
3.  **Submit Logic**: Currently, `onSubmit` only toggles local state. In a production environment, this should trigger an API call to register the user before showing the verification screen.
